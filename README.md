Аналіз вразливостей програмного забезпечення (Risk Report)

Скрипт на Python для автоматичної перевірки встановлених програм на наявність відомих вразливостей (CVE). Він звертається до NVD API, збагачує дані інформацією про активні експлоіти з CISA KEV та оцінкою ймовірності атаки EPSS, після чого вираховує пріоритети (P1–P4) і зберігає звіт у CSV.

Скрипт спочатку шукає файл inventory.json. Якщо він є — перевіряє софт з нього, якщо немає — бере базовий список з коду (MY_APPS). Результат зберігається у homework_risk_report.csv.

Під час перегляду підсумкового звіту стало зрозуміло, що частина знайдених CVE — це хибні спрацювання, які в реальному житті можна сміливо ігнорувати.

Вразливості з далекого минулого: Для Copilot, Chrome та Steam скрипт знайшов CVE 2000–2008 років. Очевидно, що сучасний Chrome 151.x чи Copilot не мають багів 20-річної давнини — це сталося через звичайний текстовий пошук (keywordSearch) у NVD API.

Некоректна прив'язка версій: Скрипт шукає баги за назвою додатка, але не перевіряє діапазон версій, де ця проблема дійсно існувала. У результаті свіжа версія програми отримує "у спадок" проблеми перших релізів.

Збіг за загальними словами: Для компонентів NVIDIA та Steam API часто повертає CVE від сторонніх бібліотек або зовсім інших продуктів, у назві яких просто є схожі слова.

Як це виправляти у нормальних проєктах: Замість простого текстового пошуку за назвою треба використовувати CPE-ідентифікатори (cpeName) та жорстко порівнювати версію програми з діапазонами вразливих версій (versionEndExcluding).

Аналіз вразливостей програмного забезпечення (Risk Report)

Скрипт на Python для автоматичної перевірки встановленого софту на вразливості (CVE). Він запитує дані з NVD API, збагачує їх інформацією про активні експлоіти з CISA KEV та ймовірністю атаки EPSS, після чого розраховує пріоритети (P1–P4) і зберігає звіт у CSV.

Інструкція із запуску:

1. Встановіть залежності:
pip install requests python-dotenv

2. (Опціонально) Додайте ключ NVD у файл `.env` для прискорення запитів:
NVD_API_KEY=your_key_here

3. Запустіть скрипт:
python homework_solution.py

Скрипт автоматично перевіряє `inventory.json`. Якщо файл відсутній, використовується базовий список `MY_APPS`. Результат зберігається у `homework_risk_report.csv`.

Аналіз хибних знахідок (False Positives)

Під час перевірки звіту виявлено ряд хибнопозитивних спрацювань:

1. Застарілі CVE: Для Chrome, Copilot та Steam підтягнулися вразливості 2000–2008 років через текстовий пошук (`keywordSearch`).
2. Відсутність прив'язки до версій: Скрипт не перевіряє діапазони вразливих версій, тому нові релізи отримують баги старих версій.
3. Схожі назви: Для компонентів NVIDIA та Steam повертаються CVE від сторонніх продуктів зі схожими словами в назві.

Рішення: Для точного аналізу необхідно використовувати CPE-ідентифікатори (`cpeName`) та порівняння діапазонів версій (`versionEndExcluding`).
